# ADR-0011: 音声の聞き間違いを、会議の中で育つ語彙と注目の情報で直す

- Status: Accepted（2026-11-08 実装）
- Owner: 牧 夢斗
- 関連：ADR-0005 §7（Gemini Live）／ADR-0006（注目度）／ADR-0009（好みエンジン）

## Context

`gemini-3.5-transcribe-live` に macOS の読み上げで作った日本語の発言を流して調べた（2026-11-08）。

| 発言 | 何も指定しないとき |
|---|---|
| ルナの案はコストをもう少し下げてほしい | どんなお味は? ｜ Estamos ｜ ストロボを少し下げてほしい。 |
| スプラウト、それって留学生も参加できる？ | ブラウト、それって留学生も |
| ジェミニとクラウドランを… | レミニとクラウドラン |

- 言語の自動判定が外れる（スペイン語に化けた回もある）
- 会議の中だけで使う言葉（キャラ名・企画名）を知らない
- 発言の終わりや3秒未満の短い発言が落ちることがある（終わりの検出の設定・雑音・音声の終わりの明示のどれでも直らなかった。モデル側の不安定さと考えている）

## Decision

認識の前と後の2段で、その会議の言葉に寄せる。

1. **認識の前**：`inputAudioTranscription` に `languageCodes: ['ja-JP']` と `customVocabulary` を渡す。語彙はキャラ名・テーマ・ステージ上の企画名・合意メモの論点・操作の言葉（`application/speech-vocabulary.ts`、最大60個）。Live のセッションを開き直すたびに作り直す。
2. **認識の後**：会議の辞書（`application/speech-lexicon.ts`）と比べて直す（`domain/transcript-repair.ts`、純粋関数）。
   - 読みの近さ：文字起こしのカタカナの並びと、辞書の言葉の読みを編集距離で比べる。濁点・小さい字・長音の違いはならして比べる。2字を超える違いは直さない
   - 表記の近さ：漢字を含む企画名（5字以上）は、最初と最後の字が同じで、違うのが漢字だけ（1〜2字）なら直す（同音の取り違え「予測→予想」）
   - 文脈の重み：ステージにいる案は +0.10、その審査員が見ている案は +0.05 だけしきい値を下げる
   - 企画名の読みは、案を作るときに Gemini に返してもらう（`reading`）
   - 論点の文章そのものは辞書に入れない（「高め→低め」のように意味を変えないため）
3. 直したことはイベントの `corrections` に、元の文字起こしは `rawText` に残す。以前は字幕に「（ブラウト→スプラウト に補正）」と出していたが、文字起こしを画面に出すのをやめたので表示しない（issue #2）。
4. ブラウザは `AudioContext` を 16kHz で作り、変換をブラウザに任せる（非対応なら従来の間引き）。

## 発言の仕分けと言い直し（issue #3）

聞き間違いを直したあと（上の 1〜2 の後）、声の発言は AI で「審査の話題か」を仕分け、残すものだけ言い直してから扱う。

- **仕分け**（`IdeaGenerationPort.triageUtterance`、速いモデルで1回）：`on_topic`（質問・感想・要望・方針・反応）／`off_topic`（雑談・アプリや機材の話）／`garbled`（聞き間違いで意味が通らない）。迷うときは `on_topic`（本物の発言を落とさない）
- **捨てる発言**（`off_topic`・`garbled`）：記録（`recordUtterance`）・好み・注目度・合意台帳・キャラへの質問のどれにも入れない。ログに `[triage] dropped` を出すだけ
- **残す発言**：言い直した1文（`summary`）を、合意台帳と AI の文脈（`recentRemarks`）、キャラへの質問、改良の指示に使う。**宛先・意図（質問／頼み／見送り／迷い）の判定は、聞こえたままの文**で行う（言い直しで「うーん」や名前が消えても挙動が変わらないように）。聞こえたままの文は `rawText` に残す
- **仕分けしない発言**：テキストで打った発言（自分で選んだ発言）、キャラの名前を呼んだ発言（話しかけだと明らか。待たずに速く返す）、合意メモの賛成／反対ボタン
- **失敗したとき**：AI が失敗したら、固定データの簡易な仕分け（アプリ・機材の話と極端に短い文だけ落とす）に切り替わる。それも通らなければそのまま扱う
- **順番**：同じ審査員の発言は、AI の返りが前後しても言った順に処理する（`utteranceChain`）
- **画面に出すもの**：声の発言は、聞こえたままも言い直したものも出さない（issue #2・#3）。画面に出るのはテキストで打った発言だけで、声の発言の内容は合意メモ（論点）やキャラの答えに現れる
- 無効にするには `UTTERANCE_TRIAGE=off`（聞こえたままの文を使う）

## 説明のしかた

「認識前の語彙での寄せ」と「読みの近さによる後からの補正」は、音声認識ではよく知られた手法。IDEA AUDITION で独自なのは、**会議の中で増えていく語彙（キャラ・企画・論点・繰り返された言葉）と、画面上の注目（ステージにいる・見ている）で寄せ方を変える**組み合わせ。「新しいアルゴリズムを発明した」とは言わない。

## Consequences / リスク

- 普通の言葉を勝手に変えない方を優先しているので、離れた聞き間違い（「のの」→「ルナ」のような2字の名前）は後段では直らない。前段の語彙に任せる
- 短い発言が落ちる問題は残る。代わりの道（Chrome の音声認識の併用、文字入力）は未着手
- しきい値は合成音声と単体テストで決めた。実機のマイク・複数人の会場での調整が必要
