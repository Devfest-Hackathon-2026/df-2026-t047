# ADR-0006: 下段の入れ替え — 注目度（会話での言及を含む）にもとづく退場

- Status: Accepted
- Owner: TBD
- Updated: 2026-11-07
- 関連：仕様書v5 第22.4・22.7章、ADR-0003、ADR-0005 §7

## Context

- 当初は「30秒ごとに、下段で最も古い案を退場させる」固定タイマーだった。
- 問題：詳細を読んでいる・回答を待っている案も退場する／みんなが話題にしている案でも古ければ消える／予告なしに消える／見られていない案が長く残る。
- ユーザーの要望：もっと頻繁に入れ替えてよい。退場の判断に「その案がどれくらい会話で取り上げられているか」を加味したい。

## Decision

下段の各案に**注目度**を持たせ、**しばらく触れられていない案のうち、注目度の最も低い案**から退場させる。

### 注目度

触れられるたびに点数を足し、時間とともに半減させる（半減期30秒）。

| 操作 | 点数 |
|---|---|
| 会話でキャラ名を呼ばれた・話しかけられた（音声・テキスト） | +6 |
| 質問された | +5 |
| 会話で企画名の一部が出た | +4 |
| つかまれた | +4 |
| 詳細を開かれた | +3 |
| カーソルが乗った | +1 |

- 会話での言及は、音声の文字起こしとテキストの発言の両方を対象にする。
  - キャラ名：英字名と読み（カタカナ・ひらがな）で照合。
  - 企画名：3文字以上の部分文字列で照合。ただし、テーマに出てこない漢字・カタカナ・英字を2文字以上含む部分に限る（「学食が」「食べた」「ように」のような誰でも使う言葉での誤検出を避ける）。カタカナとひらがなは同一視する。
- 言及の回数はカードに 💬N として表示する。

### 退場の条件

- 登場してから **10秒** は退場しない（読む時間）。
- 最後に触れられてから「**6秒＋注目度×4秒**（上限30秒）」たった案だけが候補。会話で取り上げられた案ほど長く残る。
- いま見られている案（カーソルが乗っている・詳細を開いている・つかまれている・回答待ち）は候補にしない。見られている間は「触れられていない時間」も進めない。
- 候補の中で注目度が最も低い案を選ぶ（同点なら古い方）。候補がなければ入れ替えない。

### 流れ

1. 約1秒ごとに確認し、条件を満たす案に**退場予告**（`CANDIDATE_LEAVING`）を出す。カードが暗くなり、フリップの右上（上端の枠の上）に小さなバッジ「⏳ あと N 秒で交代」を出して**10秒前からカウントダウン**する。企画名・説明には重ねない（「触れると残ります」はツールチップと読み上げで伝える）。
2. カウントダウン中に誰かが触れたら取り消し（`CANDIDATE_STAYED`）。
3. 取り消されなければ退場（`CANDIDATE_ARCHIVED`）。案は Idea BOX に保存され、キャラが BOX へ飛ぶ演出を出す。空いた枠は先読みストックから補充。
4. 予告と予告の間隔は最短 **6秒**、同時にカウントダウンする案は最大 **2件**。予告を10秒に延ばしても、誰も触れていなければおよそ6秒に1体入れ替わる（当初は30秒に1体）。
- 「次のアイデア」ボタンは、見られていない案の中で注目度の最も低い案を、予告なしで入れ替える。

### 見送り（審査員の判断ですぐ交代）（2026-11-07 追加）

- 「この案はないな」と思ったら、その案をすぐ退場させ、次のキャラと交代できる（`REJECT_CANDIDATE`）。
  - カードの右上の × ボタン（カーソルを乗せる・カウントダウン中に表示）
  - 詳細の「この案は見送る（次の人と交代）」ボタン
  - 発言（音声・テキスト）：下段のキャラ名を呼び、見送りの語を含めると見送りになる。例「ルナは却下」「MOMOはパスで」「ポポ交代で」「レオはないなー」
- 見送りの語：却下・ボツ・「はパス／パスで」・いらない・交代・退場・見送り・次の人・「はナシ」・ないわ・文末の「ないな」。「キャンパス」「没入」「少ないなと思う理由は？」のような言い方では反応しない（名前が必要、質問は対象外）。
- 見送った案も Idea BOX に保存し、理由を「見送り」と表示する（時間切れの退場は「時間切れ」）。次の案が未着でも退場させ、その枠は「AIが準備中」になる。
- 全員に「（キャラ）の案を見送りました（審査員A）。次の人と交代します」と通知する（発言の字幕は issue #2 で廃止）。
- すべての数値は環境変数で変更できる（`.env.example` の `ROTATION_*`）。

### 実装

- 判定は純粋関数（`apps/server/src/domain/attention.ts`）とセッション集約（`touch`・`registerUtterance`・`pickExitCandidate`・`beginLeaving`）。サーバーが決め、全員に同じタイミングで配信する。
- 注目しているキャラは Ephemeral の `FOCUS_CHANGED { hover, detail }` で知らせる（保存しない、他の人には中継しない）。
- 注目度は Firestore にもセッション状態の一部として保存される。復元時、退場予告は取り消す。

## Alternatives

| 案 | 採用しなかった理由 |
|---|---|
| 固定タイマーのまま間隔だけ短くする | 見ている最中に消える問題が悪化する |
| 審査員の明示的な「却下」操作で退場 | 操作が増える。直感で選ぶ体験と合わない（P1で検討可） |
| 会話との関連を Gemini で判定する | 精度は上がるが、発言ごとに1回呼び出しが増え遅延と費用がかかる。まず文字列照合で始め、誤検出が目立てば検討する |

## Consequences

- 審査員が話題にしている案ほど残り、誰も触れない案は早く入れ替わる。「人間の注目が選抜を動かす」というコンセプトを、明示的な操作なしに示せる。
- 先読みストックの消費が速くなる（入れ替えのたびに次の案が必要）。Gemini の生成呼び出しも増えるが、1回で最大8件まとめて作るため数回の入れ替えに1回程度。
- 文字列照合のため、言い換え（「あのくじのやつ」など）は拾えない。

## Verification

- テスト：言及の検出、退場候補の選び方、注目度の半減、予告と取り消し、見られている案が残ること、会話で取り上げた案が残ること（`apps/server/test/attention.test.ts`）。
- ブラウザ：予告 → 退場 → BOX へ飛ぶ演出、テキストの発言で企画名を出すと 💬1 が付くこと、予告中にカーソルを乗せると取り消されること、取り消し直後に予告が連発されないことを確認。

## 追記：誰も接続していない間は止める（2026-11-08）

- 全員が切断してもセッションは30分メモリに残るが、その間に入れ替え（そのたびに Gemini で補充）が動き続け、クレジットを使っていた。
- 接続がゼロになったら、入れ替えのタイマー・作り置きの生成・合意台帳の更新の予約を止め、退場予告も取り消す。誰かが戻ったら再開する。動いている最中の AI 呼び出し（改良・企画書）は、その1回だけ最後まで行う。
- テスト：`apps/server/test/idle.test.ts`（全員が抜けて10分たっても AI を呼ばない／戻ったら再開する）。
