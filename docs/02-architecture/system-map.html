IDEA AUDITION の全体図

完成形の姿です（2026-11-09 時点。本番は Cloud Run の revision 00026）。まだ作っている途中のものは「予定」と書いています。審査員はホストが作った部屋のリンク（/a/kqd-rmzw-tbe の形）から入り、画面とサーバーは自作のプロトコル CAMP（Collaborative Agent Mediation Protocol）で WebSocket の上を話します。予選では AI キャラが1人ずつ企画をプレゼンし、審査員全員がゴールデンブザーを押すと合格です。合格者で決勝を行い、投票で優勝を決めます。声は Gemini Live で文字にし、Gemini 3.5 Flash で審査の話だけを仕分けて使います。通話はブラウザどうしを WebRTC で直接つなぎ、つながらない回線では Cloudflare の TURN で中継します。

会場（審査員のPC） Cloud Run のコンテナ Google Cloud のサービス Vertex AI（Gemini） 開発・チーム 通話の経路（Google Cloud の外）

サービス構成図 01 / SERVICE MAP

どのツールがどのツールと、何でつながっているか。実線は毎回のやり取り、点線は毎回ではないつながり（権限・請求・端末内の処理・完成時の公開）です。線の色と太さはすべて同じにし、意味は実線と点線だけで分けています。

コンテナは1つ画面の配信、部屋の発行、通話の鍵渡し（GET /api/ice）、/camp、/voice、SessionActor が同じ Cloud Run の1台に入っています。最大1台・セッションアフィニティ（同じ人を同じ台につなぐ設定）で、全員が同じメモリ上の部屋に入ります。
Gemini を呼ぶのはサーバーだけブラウザは鍵もトークンも持ちません。サービスアカウント idea-audition-run の権限で Vertex AI と Firestore を呼びます。
合言葉は使わない部屋の ID（26の10乗通り）を知っている人だけが入れます。部屋を作るのは送り手ごとに1時間10回、同時に20部屋までに絞り、Gemini のクレジットを守ります。
声はサーバーを通らない通話の声はブラウザどうしで直接やり取りします。サーバーはつなぐための受け渡し（offer・answer・経路の候補）を CAMP の Ephemeral で中継するだけです。直接つながらない回線（テザリング・大学の Wi-Fi など）では Cloudflare の TURN が中継します。
Secret Manager には TURN のキーだけCloudflare の TURN のキーは Secret Manager に置き、起動時にサーバーへ渡します。ブラウザには数時間（6時間）で切れる接続情報だけを GET /api/ice で渡します。キーが無いときは Google の STUN だけで動きます。
マイクは1つを使い回す通話と文字起こしで同じマイクを使います。iPhone などで2回開くと通話の声が止まるためです。

好みの更新taste ← taste·0.5^(Δt/90秒) ＋ 重み·案の8軸。ブザーでの合格は強く（+1.0）、見送りはマイナス（-0.8）、迷いは弱く効きます。審査員ごとの好みは8軸のグラフで出します（予定：押さなくても常に画面に置く #12）。
選抜案を多めに作り置きし、好みとの近さ（fit）・2人の間（bridge = min(fitA, fitB)）・目新しさで点をつけ、MMR（すでに出た案に似た候補を減点する選び方）で似た案を外し、温度つきで抽選します。登場する5人のうち好みに寄せるのは2人まで。合格した案とほぼ同じ案は出しません。
合格後の文脈合格した案についての会話は生成の文脈から外し、決まった条件と否定した方向だけを残します（#6）。同じ方向の案ばかり続かないようにするためです。
合意の反映合意が大きく変わったら、古い合意で作った作り置きを捨てて作り直します。ただし、合意が変わったあとに届いた古い前提の案がまだ入ることがあります（実測計画 M2 で直す）。
落ちたときGemini が失敗したら固定データで続行。埋め込みが失敗したら 8軸だけでスコアをつけます。仕分けが失敗したら、発言を落とさずそのまま使います。

状態の移り変わり 04 / STATE MACHINES

部屋・ロビー・通話 05 / ROOMS & CALL

Google Meet と同じく、ホストが部屋を作ると推測されにくいリンクができ、そのリンクを開いた人が同じ部屋に入ります。作られていない部屋や片付けられた部屋のリンクは「見つかりません」になり、再接続はしません。ロビーでホストがテーマを入れている間に最初の挑戦者を作っておくので、開始と同時に出せます（約1.6秒 → 約0.06秒）。通話はブラウザどうしを直接つなぎ、つながらない回線では Cloudflare の TURN が中継します。

声・言及・迷い 07 / VOICE

音声は gemini-3.5-transcribe-live で文字にし、1.2秒の無音で1発言にまとめます。部屋の語彙（キャラ名・企画名・論点）で聞き間違いを直したあと、gemini-3.5-flash が審査の話かどうかを仕分けます。雑談・アプリの話・聞き取れない発言は捨て、審査の話だけを言い直して使います（キャラの名前を呼んだ発言は待たずにそのまま使う）。文字起こしは画面に出さず、残った発言だけがチャット履歴に入ります。言葉にならない迷いも拾って、見ているキャラに反応させます。マイクは通話と同じものを使います。

決勝から企画書まで 08 / FINAL

決勝では、合格者が加わるたびに案どうしが批評し合い、新しい版を作ります。タップした1人にスポットライトを当てると、名前を呼ばない質問はそのキャラに届きます。版は v1・v2… と残り、前の版に戻せます（戻した版も新しい版として積む）。企画書は決勝の間に全員分を作り置きし、優勝と同時に出します（11〜13秒 → 0秒）。前半は Gemini が書き、後半の審査レポートは記録から決まった形で作ります。PDF はブラウザの中で作るので、サーバーにファイルは残りません。

Gemini とコスト 13 / WHERE CREDITS GO

Google Cloud のクレジットを使うのは Vertex AI への呼び出しだけです。誰も接続していない間は挑戦者の交代と作り置きを止めるので、放置しても呼び出しは増えません。固定データモードは0円です。通話の中継（Cloudflare TURN）は、直接つながらない回線のときだけ使います。

場面モデル頻度の目安止まる条件
次の挑戦者gemini-3.5-flash（思考 MINIMAL）挑戦者は1人ずつ（持ち時間は既定60秒）。3案ずつ作り置き。ロビーでテーマを入れている間に2案を先に作る接続0人・決勝・投票中・固定データ
案の埋め込みgemini-embedding-001（256次元）生成のたびに数文。とても安い同上。失敗時は8軸だけで選ぶ
質問への回答・合意の更新gemini-3.5-flash質問のたび。合意は発言が少し途切れたとき・行動の直後にまとめて固定データ
発言の仕分け・言い直しgemini-3.5-flash声の発言のたび（キャラの名前を呼んだ発言は仕分けない）マイクオフ・固定データ
迷いへの別案gemini-3.5-flash迷いを検出したとき。同じ案は25秒あける固定データ・間隔中
相互批評・改良・企画書gemini-3.8-flash（思考 LOW）合格・改良の頼みのたび。企画書は決勝の全員分を作り置きし、版が変わったら作り直す固定データ
音声の文字起こし（予定：声の調子も）gemini-3.5-transcribe-liveマイクをオンにしている間ずっとマイクオフ

CAMP とOSSへの道 15 / PROTOCOL & OSS

CAMP は TCP や WebSocket の仲間ではなく、その上に載るアプリケーション層のプロトコルです。WebSocket は「届ける」だけで、4人がほぼ同時にブザーを押したときに合格を1回だけにする方法、返事の前に切れた操作をどうするか、遅れて返った AI の結果をどう扱うかは決めてくれません。そこを決めているのが CAMP です（ADR-0010、docs/protocol/camp-v1.md）。

  CAMP["CAMP v1（自作）<br/>直列処理と seq · 重複排除 · 再接続 · 古い AI 結果を捨てる · 部屋"]
  WS["WebSocket（RFC 6455）<br/>双方向・メッセージ単位で届ける"]
  TLS["TLS（暗号化）"]
  TCP["TCP<br/>順番どおり確実に届ける"]
  IP["IP"]

プロトコルとして決めることCAMP v1 の答え
送れるメッセージhello・welcome・command・result・event・ephemeral・signal・protocol_error
誰が入れるかアプリが作った部屋だけ。ない部屋は ROOM_NOT_FOUND（終了コード 4404）
処理の順序部屋ごとに1件ずつ。Event に欠番なしの seq と snapshot 全体
同時操作の衝突状態の前提条件で判定。対象の版は expected.rev → STALE_VERSION
二重処理と再接続commandId ごとに結果を覚えて同じ result を返す。再接続したら同じ ID で送り直す
AI の遅れた結果部屋を作り直す前に始まった結果は捨てる（epoch）
バージョン・壊れたメッセージ・送りすぎprotocol_error で理由を返し、決まった終了コードで閉じる
いまの状態@camp-protocol/kit として実装し、適合テストと仕様書（SPEC.md）をそろえた。GitHub の camp-protocol/camp と npm の @camp-protocol は確保済み。完成したら英語の履歴で公開し直し、npm に出す。
アプリとの関係IDEA AUDITION は同じリポジトリの packages/camp を読んでいる。npm に出したら、読み込み先を npm の版に切り替える（import はそのまま）。
アプリの言葉を持たないCAMP の中にアプリの語彙が混ざらないことを、境界テストで毎回確かめている。
