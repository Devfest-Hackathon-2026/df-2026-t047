## P0：デモの質に直接効く（最優先）

直したら見出しの [ ] を [x] にする。

### [x] 1. 1回選んだだけで、下段が同じ方向の案ばかりになる
- **見えたこと**：1回目で「自炊が苦手な学生の食堂」を1つ選抜しただけで、そのあと下段の5案がほぼ全部「学生の食事」の案になった（まちの総菜交換留学、まかないのない食堂、1坪だけの超ミニ学食、放課後まかない宅配便…）。「🧭 まだ出ていない方向」や「🎲 ワイルドカード」の札が付いた案まで食事の案だった。決勝の3案も全部食事の案になり、比べる意味が薄れた
- **数字**：💡 好みに合わせた案は22回出て、選ばれたのは0回。選ばれた3案は 🧭（2）と 🎲（1）から
- **原因の見立て**：
  - 合意台帳の「合意」（例「地元で自炊が苦手な学生を支援する」）が、すべての生成に方向として渡っている
  - 好みの信頼度が低い（信号が3つ未満）うちから、好みに合わせた案の枠が多すぎる
- **直し方**：
  - 合意を参考にするのは 💡 の枠だけにする。🧭 と 🎲 の枠には「合意や決勝の案から離れること」を指示する
  - 決勝の案と意味の近さ（埋め込み）が一定以上の案は、🧭 と 🎲 の枠から外す
  - 信頼できるまでは 💡 を5枠中1枠までにする

- **対応**：生成の指示で「合意に反しない＝全部をそこに寄せる、ではない」と明記し、合意や選ばれた案を伸ばしてよいのは 💡・🤝 の枠だけにした。🧭・🎲 の枠には「選ばれた案・合意と同じ対象・手段を使わず、テーマの別の側面から」と具体的な案名つきで頼む。好み・折衷は5枠中2枠までに減らし、🧭・🎲 を選ぶときは決勝の案に近い候補を強く減点する（`test/diversity.test.ts`）

### [x] 2. 下段の入れ替えが速すぎて、読めないうちに消える
- **見えたこと**：何もしなくても約6秒ごとに1案が入れ替わる。4分で34案がアイデアBOXに流れた。カードを読んでいる最中に「あと3秒で交代」が出る。4人で話しながら選ぶには速すぎる
- **費用**：生成と埋め込みが1部屋あたり1分に約10回ずつ呼ばれる。15分のデモなら generateIdeas が約150回
- **直し方**：入れ替えの最短間隔を6秒から15〜20秒に、同時に退場予告を出す数を2から1にする（`DEFAULT_ROTATION` の `minGapMs`・`maxConcurrentLeaving`）。合意台帳の更新でまとめて捨てる案も1回1案までにする。費用も半分以下になる

- **対応**：入れ替えを18秒に1案まで、同時の退場予告を1案までにした（`DEFAULT_ROTATION`）。生成の呼び出しも約3分の1になる

### [x] 3. 合意メモが、人がしていない判断を書いてしまう
- **見えたこと**：
  - 何も却下していないのに「却下：若者の直接的な居住や起業は避ける」と書かれた
  - AI（ルナ）の答え「定期訪問の会員制や店舗の共同出資で収益を得る」が、そのまま「合意」になった
- **なぜ困るか**：合意メモは「人間たちが決めたこと」の記録なので、AI の提案や推測が混ざると信用を失う。計画中の「対話の実測」の土台でもある
- **直し方**：
  - 合意・却下の根拠には、人の発言か操作（選抜・不合格・投票）だけを使う。AI の答えは根拠にしない
  - 各項目に、根拠になった発言（誰が・何と言ったか）を必ず付けさせる
  - 却下は、不合格の操作か否定的な発言があるときだけにする

- **対応**：台帳の材料から、下段の自動の入れ替え（誰の判断でもない）を外した。指示を「根拠は人の発言と行動だけ。AI の答えや推測から論点を作らない」「反対は、はっきり否定したか不合格にしたときだけ」「行動から論点を作るのは、同じ人が同じ方向を2回以上選んだときだけ」に変えた。サーバー側でも、発言の番号にも行動にも結び付かない論点、企画名そのものの論点、1回選んだだけの行動から作った論点は捨てる（`test/consensus.test.ts`。直したあとに遊んで、1回の選抜で「一坪ダンボール横丁」が論点になるのを見つけて追加で直した）

### [x] 4. 「〜を足して。〜は？」と言うと、質問として答えるだけで改良されない
- **見えたこと**：「ルナ、学生が毎週通いたくなる仕掛けを足して。収益はどうやって出す？」は質問として扱われた。答えは返ったが、版は Ver.2 のまま変わらなかった
- **直し方**：「足して」「変えて」「下げて」「〜して」などの頼みの言葉があれば、答えに加えて改良も行う。少なくとも「改良も頼みますか？」と1回で押せるボタンを出す

- **対応**：決勝の案への発言に頼みの言葉（足して・変えて・下げて・〜にして・ほしい など）があれば、質問と一緒でも改良し、質問にも答える。質問だけなら答えるだけ（`test/actor.test.ts`）

### [x] 5. 「うーん」から作った別案の中身が薄い
- **見えたこと**：
  - 理由の欄が発言の生の切れ端になっている（「迷いを受けて『うーん、ルナの案はちょっと微妙かも。どう』」）
  - 「残す強み」と「今回の改良ポイント」が空だった
  - 詳細画面の質問欄に「うーん、ちょっと微妙かも…」と入れた場合は、迷いとして扱われず、質問への答えだけが返った
- **直し方**：
  - 別案を作るときにも、残す強み・改良点・短い理由を Gemini に返させる
  - 詳細画面の質問も、迷いの検出に通す

- **対応**：別案を作るときに「残した良さ」「変えた点」「変えた理由のひとこと」も Gemini に返させ、版に入れる。理由は「迷いを受けて：大がかりすぎたので小さく始める形に」の形にし、発言をそのまま貼らない。詳細画面の質問欄に入れた「うーん」も迷いとして扱い、別案を出す（`test/taste.test.ts`）
