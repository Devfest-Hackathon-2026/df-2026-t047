# ADR-0008: 優勝案の企画書と審査レポートを PDF で渡す

- Status: Accepted（2026-11-08 実装）
- Owner: TBD
- Updated: 2026-11-08
- 関連：ADR-0005（AI）、ADR-0007（合意台帳）、テストユーザーのフィードバック（2026-11-07）

## Context

テストユーザーから次の声があった。
- 「最終的にアイデアを決めるところまで？ 企画書まで作れると、その後の活動につなげやすい」
- 「結局どう会議が変わるのかイメージしづらい」

決まった案だけでは、会議の後に何を持って動けばよいかが見えない。決定までの審査の流れも含めた成果物を、アプリの中で渡す。

## Decision

### 流れ
1. 優勝が決まった瞬間に、サーバーが企画書の作成を自動で始める（`proposal.status = generating`）。
2. 優勝画面に「企画書と審査レポートを作成中…」を表示し、できたら（`PROPOSAL_UPDATED`）「📄 企画書PDFをダウンロード」ボタンが現れる。
3. ボタンを押すと、その場で PDF を作ってダウンロードする（ファイル名 `IDEA_AUDITION_企画書_<企画名>.pdf`）。
4. 失敗したら「もう一度作る」（`REGENERATE_PROPOSAL`）。サーバー再起動で作成が途切れたら、復元時に作り直す。

### PDF の中身（2部構成）
| 部 | 内容 | 作り方 |
|---|---|---|
| 第1部 企画書 | 企画名・一言・背景・課題・対象者・提供する価値・概要・主な内容・進め方（段階と期間）・体制・予算の目安・リスクと対策・成果の測り方・次の一手・要検証の前提 | Gemini（gemini-3.8-flash）。改良の経緯・合意台帳・相互批評・質疑・他の最終候補を材料として渡す。記録に無い数字や事実は断定させず「要検証の前提」に挙げさせる |
| 第2部 審査レポート | 審査の数字（検討した案・最終オーディション・見送り・時間切れ・改良回数・合意した方針）、合意した方針と賛否の時系列、改良の経緯（版ごとの理由・改善・💡）、相互批評、質問と回答、決め方（得票）、他の最終候補、見送った・入れ替わった案 | **LLM を使わず記録（snapshot）からそのまま作る**。作り話が入らない |

### PDF の作り方
- ブラウザの中で A4 の紙面（白地）を描き、`html2pdf.js`（html2canvas＋jsPDF）で画像化して PDF にする。
- 利点：日本語フォントをそのまま使える。サーバー（Cloud Run）に重い処理や Chromium を足さない。1クリックでダウンロードできる。
- PDF ライブラリ（約935KB）はボタンを押したときだけ読み込む。

## Alternatives

| 案 | 採用しなかった理由 |
|---|---|
| ブラウザの印刷ダイアログ（PDF として保存） | ダウンロードまでの操作が増える。保存先の選択が人によって違う |
| サーバーで Puppeteer / Chromium | Cloud Run のイメージが重くなり、起動とデプロイが遅くなる |
| jsPDF に日本語フォントを埋め込んで文字のまま出す | フォントファイルが数MB。文字を選択できる利点はあるが、組版を自前で書く必要がある |

## Consequences

- 会議の終わりに「決まった案＋決まるまでの経緯」が手元に残る。フィードバックの「会議がどう変わるか」への具体的な答えになる。
- PDF の文字は画像なので、選択・検索・コピーができない（1.2MB／4ページ程度）。必要になったら、サーバー側での生成か、文字のまま出す方式に切り替える。
- 企画書の作成に 15 秒前後かかる（実測 15.1秒）。その間は「作成中」を表示する。

## Verification

- テスト（`apps/server/test/proposal.test.ts`、3件）：優勝で自動作成→全員に配信（改良の経緯を材料に渡す）、失敗→作り直し、作成中の再起動→復元時に作り直し。
- ブラウザ＋本物の Gemini（2026-11-08）：ソロで2案を昇格・質問 → 優勝 → 「作成中」→ 15.1秒でボタン出現 → `IDEA_AUDITION_企画書_農園ガチャランチ.pdf`（4ページ・1.2MB、押してから0.25秒）。紙面を画像で確認し、日本語の表示・2部構成・表の区切りに問題がないことを確認。
