## 次にやること（優先順）

1. **P1-1 最新版の一貫性**
   - 「今の案」（企画名・説明・誰の・困りごと・どう解く・今の特徴）を、版ごとに一式で持つ
   - 改良で変えた点（`improvementPoints`）を、前の版から足し合わせて「今の特徴」として出さない。変えた点は、その版の差分として「履歴」にだけ出す
   - 詳細・ステージ・優勝画面・文章コピー・PDF が、同じ最新版を見るようにそろえる
   - 改良の生成で、`outline`（誰の・困りごと・どう解く）を必ず新しい案に合わせて書き直させる（今は前の版のまま残ることがある）
   - 開いている詳細画面も、版が更新されたら全部入れ替える
   - テスト：改良のあと、旧版の条件が現行の画面・コピー・PDF に残らない
2. **P1-3 操作バー**：審査員の札と、発言・補助操作を別の行にする。ラベルは折り返さない。入力欄の幅を確保する
3. **P2-3 自分のブザー**：「あなた」の印、押したらチェック、カーソルの名札をブザーに重ねない
4. **P2-2 待機室へ飛ぶ演出**：合格の見せ場 → キャラの小さなコピーが枠へ移動 → 枠が光る。動きを減らす設定では短いフェード
5. **P1-2 の残り**：1363×936 と 1280×720 で、タイトル・一文の説明・投票ボタンが欠けないことを実画面で確かめる。キャラがフリップを手に持つ構図
6. **P2-1 の残り**：ブザーの近くに今の対象の名前。サーバーで、ブザーに `instanceId` に加えて回（round）も見る
7. **P3 の残り**：足元の影、床の反射

実ブラウザ4タブで「未投票 → 1/4 → 3/4 → 4/4 → 合格 → 待機室 → 3人 → 決勝 → 改善依頼 → 投票 → 優勝」を通し、直す前と後の画像を残す。回帰テストは「旧版が現行に混ざらない」「4/4 で一度だけ合格」「3枠で一度だけ決勝」「古い回の票が次の案に入らない」。
